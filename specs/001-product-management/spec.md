## 명확화 (Clarifications)

### Session 2026-10-07

- Q: 주문 이력이 있는 상품을 삭제하면 어떻게 처리해야 합니까? → A: 논리 삭제 (모든 상품을 삭제 표시만 하고 데이터 보존)
- Q: 두 운영자가 같은 상품을 동시에 수정하려 할 때 어떻게 처리해야 합니까? → A: 충돌 감지 (나중 저장 거부 후 최신 내용 재조회 안내)
- Q: 상품 식별 코드는 시스템이 자동으로 만듭니까, 운영자가 직접 입력합니까? → A: 자동 부여 + 직접 입력 허용 (비우면 자동 생성, 입력 시 중복 검사, 한 번 정해진 코드는 수정 불가)
- Q: 상품 하나에 첨부할 수 있는 이미지의 개수와 파일 용량 상한은 얼마로 합니까? → A: 상품당 최대 10장, 장당 5MB 이하 (JPG·PNG)
- Q: (분석 후속) 고객 노출 요구는 이 기능에서 어떤 범위로 다룹니까? → A: 인증 없는 읽기 전용 고객 조회 API를 이 기능에 포함 (FR-018)
- Q: 상품이 품절로 바뀐 뒤 재고가 다시 보충되면, 판매 상태를 자동으로 "판매중"으로 되돌립니까? → A: 자동 복귀 ("품절"만 "판매중"으로 복귀, "숨김"은 유지)

## 사용자 시나리오 및 테스트 (User Scenarios & Testing) *(필수)*

### 사용자 스토리 1 - 상품 등록 및 조회 (우선순위: P1)

운영자가 판매할 상품의 이름, 설명, 가격, 재고, 카테고리, 이미지를 입력해 새 상품을 등록하고, 등록된 상품의 목록과 상세 정보를 확인한다.

**이 우선순위인 이유**: 상품이 등록되지 않으면 커머스의 어떤 기능(진열, 주문, 결제)도 성립하지 않는다. 이 스토리만 구현해도 상품 데이터를 쌓고 확인할 수 있어 최소한의 가치를 제공한다.

**독립 테스트**: 운영자가 상품 등록 화면에서 필수 정보를 입력해 저장한 뒤, 상품 목록과 상세 화면에서 같은 정보를 확인할 수 있으면 완전히 테스트된 것이다.

**인수 시나리오**:

1. **Given** 운영자가 상품 등록 화면에 있고, **When** 필수 항목(상품명, 가격, 카테고리)을 입력하고 저장하면, **Then** 상품이 생성되어 상품 목록에 나타난다.
2. **Given** 등록된 상품이 있고, **When** 운영자가 목록에서 해당 상품을 선택하면, **Then** 입력했던 모든 정보가 상세 화면에 표시된다.
3. **Given** 운영자가 필수 항목을 비워 둔 채, **When** 저장을 시도하면, **Then** 저장되지 않고 누락된 항목이 무엇인지 안내된다.

---

### 사용자 스토리 2 - 상품 정보 수정 및 판매 상태 관리 (우선순위: P2)

운영자가 등록된 상품의 가격, 설명, 재고, 이미지 등을 수정하고, 상품의 판매 상태(판매중, 품절, 숨김)를 바꾼다.

**이 우선순위인 이유**: 가격 변경, 재고 보충, 판매 중단은 운영 중 매일 발생하는 작업이다. 등록 다음으로 가치가 크며, 상품 등록과 독립적으로 테스트할 수 있다.

**독립 테스트**: 기존 상품의 가격과 판매 상태를 변경한 뒤, 목록과 상세 화면에 변경 내용이 반영되는지 확인한다.

**인수 시나리오**:

1. **Given** 판매중인 상품이 있고, **When** 운영자가 가격을 수정해 저장하면, **Then** 이후 조회되는 상품 정보에 새 가격이 표시된다.
2. **Given** 판매중인 상품이 있고, **When** 운영자가 상태를 "숨김"으로 바꾸면, **Then** 고객에게 노출되는 상품 목록에서 해당 상품이 보이지 않는다.
3. **Given** 상품의 재고가 0이 되었을 때, **When** 재고가 갱신되면, **Then** 상품 상태가 자동으로 "품절"로 표시된다.
4. **Given** "품절" 상태의 상품이 있고, **When** 재고가 1 이상으로 보충되면, **Then** 상태가 자동으로 "판매중"으로 바뀐다. 단, "숨김" 상태의 상품은 재고가 보충되어도 "숨김"으로 유지된다.
5. **Given** 두 운영자가 같은 상품 수정 화면을 열어 둔 상태에서, **When** 한 운영자가 먼저 저장한 뒤 다른 운영자가 저장하면, **Then** 나중 저장은 거부되고 최신 내용을 다시 불러오라는 안내가 표시된다.

---

### 사용자 스토리 3 - 상품 검색, 필터링 및 정렬 (우선순위: P3)

운영자가 많은 상품 중에서 상품명, 카테고리, 판매 상태로 원하는 상품을 빠르게 찾고, 등록일이나 가격 순으로 정렬한다.

**이 우선순위인 이유**: 상품 수가 늘어날수록 필요해지지만, 상품이 적을 때는 목록만으로도 운영이 가능하다.

**독립 테스트**: 여러 상품을 등록한 뒤 검색어, 카테고리, 상태 조건을 적용했을 때 조건에 맞는 상품만 표시되는지 확인한다.

**인수 시나리오**:

1. **Given** 여러 카테고리의 상품이 등록되어 있고, **When** 운영자가 특정 카테고리를 선택하면, **Then** 해당 카테고리의 상품만 목록에 표시된다.
2. **Given** 상품 목록이 있고, **When** 운영자가 상품명의 일부를 검색하면, **Then** 이름에 해당 문자열이 포함된 상품만 표시된다.
3. **Given** 검색 조건에 맞는 상품이 없을 때, **When** 검색 결과가 표시되면, **Then** "결과 없음" 안내가 나타난다.

---

### 사용자 스토리 4 - 상품 삭제 (우선순위: P3)

운영자가 더 이상 판매하지 않는 상품을 삭제한다. 삭제는 논리 삭제(삭제 표시)로 처리되어 운영자 목록과 고객 화면에서는 사라지지만, 이미 주문 이력이 있는 상품의 과거 주문 정보는 훼손되지 않고 계속 조회된다.

**이 우선순위인 이유**: 잘못 등록된 상품을 정리하는 데 필요하지만, 숨김 상태로 대체할 수 있어 우선순위가 낮다.

**독립 테스트**: 상품을 삭제한 뒤 목록에서 사라지는지, 삭제 전에 확인 절차가 있는지 확인한다.

**인수 시나리오**:

1. **Given** 등록된 상품이 있고, **When** 운영자가 삭제를 요청하면, **Then** 삭제 여부를 다시 확인하는 절차가 표시된다.
2. **Given** 삭제 확인 절차에서, **When** 운영자가 확인하면, **Then** 상품이 목록에서 사라진다.
3. **Given** 주문 이력이 있는 상품을 삭제했고, **When** 과거 주문 내역을 조회하면, **Then** 해당 상품의 주문 당시 정보가 그대로 표시된다.

---

### 예외 상황 (Edge Cases)

- 가격에 0 이하의 값이나 숫자가 아닌 값을 입력하면 어떻게 되는가? → 저장되지 않고 가격은 0보다 큰 정수여야 한다는 안내가 표시된다.
- 재고에 음수를 입력하면 어떻게 되는가? → 저장되지 않고 재고는 0 이상의 정수여야 한다는 안내가 표시된다.
- 옵션 조합 중 일부만 재고가 0이면 상품과 해당 옵션은 어떻게 표시되는가? → 재고가 0인 옵션 조합만 품절로 표시하고, 상품은 모든 옵션 조합의 재고가 0일 때만 품절이 된다.
- 같은 옵션 조합을 중복으로 정의하면 어떻게 되는가? → 저장되지 않고 중복된 옵션 조합이 안내된다.
- 이미 존재하는 상품명이나 상품 코드로 등록하면 어떻게 되는가? → 상품 코드가 중복되면 등록이 거부되고 중복 사유가 안내된다.
- 두 운영자가 동시에 같은 상품을 수정하면 어떻게 되는가? → 먼저 저장된 변경이 있으면 나중 저장은 거부되고, 최신 내용을 다시 불러오도록 안내된다.
- 주문 이력이 있는 상품을 삭제하려 하면 어떻게 되는가? → 이력 유무와 관계없이 논리 삭제되며 과거 주문 정보는 보존된다.
- 허용되지 않는 형식이나 지나치게 큰 이미지를 업로드하면 어떻게 되는가? → JPG·PNG 이외 형식, 5MB 초과, 상품당 10장 초과 업로드는 거부되고 사유가 안내된다.
- 존재하지 않는(이미 삭제된) 상품의 주소로 접근하면 어떻게 되는가? → "존재하지 않는 상품"으로 안내되고 상세 정보는 표시되지 않는다(404).

## 요구사항 (Requirements) *(필수)*

### 기능 요구사항 (Functional Requirements)

- **FR-001**: 시스템은 반드시 운영자가 상품명, 설명, 가격, 재고 수량, 카테고리를 입력해 상품을 등록할 수 있어야 한다. 옵션이 있는 상품은 재고 수량을 옵션 조합별로 입력한다.
- **FR-002**: 시스템은 반드시 상품에 0장 이상 10장 이하의 이미지를 첨부할 수 있어야 하며(이미지 없이도 등록할 수 있다), 이미지가 있으면 대표 이미지를 정확히 하나 지정해야 한다. 대표 이미지를 삭제하면 남은 첫 번째 이미지가 자동으로 대표가 된다. 이미지는 JPG 또는 PNG 형식만 허용하며, 상품당 최대 10장, 장당 5MB 이하로 제한한다. 제한을 넘는 업로드는 거부하고 사유를 안내해야 한다.
- **FR-003**: 시스템은 반드시 상품명, 가격, 카테고리가 없는 상품은 저장하지 않고 누락된 항목을 안내해야 한다.
- **FR-004**: 시스템은 반드시 가격은 0보다 큰 값, 재고는 0 이상의 정수만 허용해야 한다.
- **FR-005**: 시스템은 반드시 각 상품에 고유한 식별 코드를 부여하고, 중복된 코드의 등록을 막아야 한다. 운영자가 코드를 비워 두면 시스템이 자동 생성하고, 직접 입력하면 중복 검사 후 사용한다. 한 번 정해진 코드는 수정할 수 없다.
- **FR-006**: 시스템은 반드시 등록된 상품의 목록과 개별 상품의 상세 정보를 조회할 수 있어야 한다.
- **FR-007**: 시스템은 반드시 운영자가 등록된 상품의 모든 정보를 수정할 수 있어야 한다. 운영자가 편집을 시작한 이후 다른 운영자가 먼저 같은 상품을 저장했다면, 나중 저장은 거부하고 최신 내용을 다시 불러오도록 안내해야 한다(자동 덮어쓰기 금지).
- **FR-008**: 시스템은 반드시 운영자가 상품의 판매 상태를 판매중 또는 숨김으로 지정할 수 있어야 한다. 품절은 재고에서 자동으로 결정되며 운영자가 직접 지정하지 않는다(FR-009). 숨김 상태의 상품은 고객에게 노출되지 않아야 한다.
- **FR-009**: 시스템은 반드시 재고가 0이 되면 상품을 품절로 표시해야 한다. 품절 상태의 상품은 재고가 1 이상으로 보충되면 자동으로 "판매중"으로 복귀해야 하며, "숨김" 상태는 재고 변화와 무관하게 유지해야 한다.
- **FR-010**: 시스템은 반드시 상품명 검색, 카테고리·판매 상태 필터, 등록일·가격 정렬을 제공해야 한다.
- **FR-011**: 시스템은 반드시 상품 목록을 페이지 단위로 나누어 보여주어야 한다.
- **FR-012**: 시스템은 반드시 상품 삭제 전에 확인 절차를 거치도록 해야 한다. 삭제는 모든 상품에 대해 논리 삭제(삭제 표시, 데이터 보존)로 처리하며, 삭제된 상품은 운영자 목록과 고객 화면에서 제외하되 과거 주문 정보는 계속 조회할 수 있어야 한다.
- **FR-013**: 시스템은 반드시 상품의 생성·수정·삭제 이력(누가, 언제, 무엇을)을 기록해야 한다.
- **FR-014**: 시스템은 반드시 상품 관리 기능을 권한이 있는 운영자에게만 허용해야 한다.
- **FR-015**: 시스템은 반드시 상품에 옵션(예: 색상, 사이즈)을 정의하고, 옵션 조합별로 재고 수량을 따로 관리할 수 있어야 한다. 가격은 상품 단위로 하나이며 옵션별로 다르지 않다.
- **FR-016**: 시스템은 반드시 옵션이 있는 상품은 모든 옵션 조합의 재고가 0일 때 품절로 표시해야 하며, 옵션이 없는 상품은 상품 자체의 재고로 판단해야 한다.
- **FR-017**: 시스템은 단일 판매자(자사 쇼핑몰)를 전제로 하므로, 권한이 있는 모든 운영자가 모든 상품을 관리할 수 있어야 한다.
- **FR-018**: 시스템은 반드시 고객 노출용 읽기 전용 상품 조회(목록·상세)를 인증 없이 제공해야 한다. 판매중·품절 상품만 노출하고, 숨김·삭제된 상품은 목록에서 제외하며 상세 접근은 존재하지 않는 상품(404)으로 처리해야 한다. 고객용 응답에는 정확한 재고 수량을 포함하지 않고 품절 여부만 포함한다.

### 핵심 엔터티 (Key Entities)

- **상품(Product)**: 판매 대상. 식별 코드, 상품명, 설명, 가격, 재고 수량, 판매 상태, 삭제 여부(삭제 표시 시각), 등록일·수정일을 가진다. 하나의 카테고리에 속하고 여러 이미지를 가진다.
- **카테고리(Category)**: 상품을 분류하는 단위. 이름을 가지며 여러 상품을 포함한다.
- **상품 옵션(Product Option)**: 상품의 선택 항목(예: 색상, 사이즈)과 그 값. 옵션 값의 조합마다 재고 수량을 가진다. 옵션이 없는 상품도 있을 수 있다.
- **상품 이미지(Product Image)**: 상품에 첨부된 이미지. 대표 여부와 표시 순서를 가진다.
- **변경 이력(Change Log)**: 상품에 대한 생성·수정·삭제 기록. 변경자, 변경 시각, 변경 내용을 가진다.

## 성공 기준 (Success Criteria) *(필수)*

### 측정 가능한 결과 (Measurable Outcomes)

- **SC-001**: 운영자가 새 상품 하나를 등록하는 데 3분 이내가 걸린다.
- **SC-002**: 운영자가 상품 1만 개 중에서 원하는 상품을 검색하여 찾는 데 5초 이내가 걸린다.
- **SC-003**: 상품 정보를 수정하면 1분 이내에 고객에게 보이는 정보에 반영된다.
- **SC-004**: 처음 사용하는 운영자의 90%가 별도 교육 없이 첫 시도에 상품 등록을 완료한다. (출시 후 사용성 지표이며 별도 구현 작업은 없다.)
- **SC-005**: 잘못된 입력(필수 항목 누락, 음수 재고 등)의 100%가 저장 전에 차단되고 원인이 안내된다.
- **SC-006**: 주문 이력이 있는 상품을 삭제하더라도 과거 주문 정보가 손실되는 사례가 0건이다.

## 가정 (Assumptions)

- 상품을 관리하는 사용자는 인증된 운영자이며, 고객은 상품을 조회만 한다. 고객용 화면 자체는 이 기능의 범위 밖이지만, 고객 노출 규칙을 검증하기 위한 읽기 전용 조회 API(FR-018)는 이 기능에 포함한다.
- 운영 환경의 인증 방식(SSO, JWT 등)은 별도 기능에서 정한다. 개발·테스트 환경은 HTTP Basic 인증으로 대체한다.
- 결제, 주문 처리, 배송은 별도 기능이며, 이 기능은 상품 데이터의 관리만 다룬다.
- 가격은 단일 통화(원화)로 관리하며 옵션과 무관하게 상품당 하나이다. 할인·쿠폰·프로모션은 범위에서 제외한다.
- 판매자는 하나뿐인 자사 쇼핑몰이며, 판매자별 상품 소유와 권한 분리는 범위에서 제외한다.
- 카테고리는 미리 정의되어 있거나 별도로 관리되며, 이 기능에서는 상품에 지정만 한다. 카테고리 관리 기능이 제공되기 전에도 등록이 막히지 않도록 기본 카테고리 "미분류"를 이 기능의 마이그레이션이 제공한다.
- 운영자가 사용하는 화면은 웹 환경을 기본으로 하며, 모바일 전용 화면은 범위에서 제외한다.
- 이미지는 JPG, PNG 형식과 상품당 10장·장당 5MB 제한을 따른다.
- 상품 일괄 등록(대량 업로드)은 이번 범위에서 제외한다.
